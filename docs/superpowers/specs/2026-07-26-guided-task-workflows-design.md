# 三入口引导式工程工作台设计

## 目标

把当前集中在同一页的 GitLab 与 Ironforge 操作拆成三个任务入口。工程师先选择“今天要做什么”，进入后一次只处理一个步骤，不需要预先理解 Git、Branch、Commit、Push、Tag 或 MR。

## 首页

项目首页显示当前项目名称、本地路径、服务器连接状态和三个任务入口：

1. **上传整个工程**
   - 说明：把源文件、参考资料、交付文件和配置更新到公司服务器。
2. **提交图纸到铁炉堡**
   - 说明：选择交付文件夹、保存交付版本并提交管理员审核。
3. **获取项目和图纸**
   - 说明：把云端项目下载到电脑、获取同事改动或下载已发布图纸。

首页不展示文件清单、审核人、版本标记或编辑器。每个入口使用清晰的动词和结果描述，不显示命令名称。

## 路径一：上传整个工程

该路径同步当前仓库的全部有效改动，包括 `source`、`reference`、`output`、`charge.json` 和合法根目录配置。

步骤：

1. **选择保存位置**
   - 选择已有工作分支或创建新工作分支。
2. **检查改动**
   - 按顶层目录分组展示新增、修改和删除。
   - 文件范围只读，不能在此取消单个工程文件。
3. **填写本次更新标题**
   - 该字段写入 Git Commit message。
4. **确认上传**
   - 展示分支、文件数量、删除项和本次更新标题。
   - 用户确认后执行 Commit 与 Push。
5. **完成**
   - 展示提交编号、服务器分支和打开 GitLab 的入口。

该路径不显示本次交付标签、交付清单、审核人或管理员审核，不创建 MR。

## 路径二：提交图纸到铁炉堡

进入该路径时先检查 `source` 和 `reference` 是否有未上传修改。

- 存在未上传修改：停止交付流程，提示“工程源文件还有改动没有上传”，提供返回首页和进入“上传整个工程”的按钮。
- 不存在未上传修改：进入交付向导。
- 不自动把 `source` 或 `reference` 混入交付提交。

步骤：

1. **选择交付文件夹**
   - 扫描非空 `output/<domain>/<package>`。
   - 母文件夹是最小选择单位，勾选后包含内部全部子文件。
2. **核对文件变化**
   - 按真实文件夹层级显示目录树。
   - 默认展开本次有变化的路径，无变化的路径默认收起。
   - 文件夹显示汇总，如“新增 2”“修改 1”。
   - 文件显示绿色“新增”、黄色“已修改”、红色“已删除”。
   - 子文件只能核对，不能单独取消，防止遗漏配套资料。
3. **填写上传与版本信息**
   - “本次更新标题”：写入 Git Commit message。
   - “本次交付标签”：用户自由填写 Git Tag 名称，例如 `T2设变零件`。
   - 交付标签可留空；填写时必须在 Commit 前检查本地和远端唯一性。
   - 已存在的标签不得覆盖、移动或强制更新。
   - Tag annotation 复用“本次更新标题”，不要求第二份 Tag 说明。
4. **上传交付内容**
   - 根据已选母文件夹增量更新交付清单 `charge.json`。
   - 确认后执行 Commit、Push，以及可选 Tag 创建与 Push。
5. **填写审核内容**
   - “本次交付标题”：写入 GitLab MR title。
   - “交付补充说明（可选）”：写入 GitLab Markdown description。
   - 支持飞书云文档链接、PDF 和图片附件。
6. **选择审核人**
   - 至少选择一位审核人。
7. **提交管理员审核**
   - 创建 GitLab MR。
   - 管理员合并 MR 后即完成 Ironforge 发布，不显示第二个发布按钮。
8. **完成**
   - 展示等待审核、需要修改、已审核和已发布状态。

## 路径三：获取项目和图纸

该入口先展示三个明确子任务：

### 把云端项目下载到这台电脑

- 适用于新电脑、本机没有该项目或需要添加其他项目。
- 选择管理员已经创建且当前账号有权访问的 GitLab 项目。
- 选择本机空目录或新目录。
- 下载完整工作副本、Git LFS 文件和版本记录。
- 不影响已有项目。

### 获取同事刚上传的改动

- 适用于本机已经存在的项目。
- 选择正式分支、同事工作分支或版本标签。
- 下载前预览新增、修改和删除。
- 本地存在未上传修改时停止，不自动覆盖或合并。
- 用户确认后才更新当前项目文件夹。

### 下载铁炉堡已发布图纸

- 按项目、零件名、交付文件夹或交付标签搜索。
- 按文件夹层级查看已发布内容。
- 支持下载整个交付文件夹或单个文件。
- 每次允许选择下载目录，并可记住项目默认下载目录。
- 默认不写入 Git 工程；导入 `reference` 必须另行明确确认。

## 通俗术语

界面主文案固定使用：

| 技术对象 | 页面名称 |
| --- | --- |
| GitLab sync / Push | 上传工程改动 |
| Branch | 工作分支 |
| Commit message | 本次更新标题 |
| Git Tag | 本次交付标签 |
| MR title | 本次交付标题 |
| MR description | 交付补充说明（可选） |
| Reviewer | 审核人 |
| `charge.json` | 交付清单 |
| output package | 交付文件夹 |
| Merge Request | 提交管理员审核 |

必要时可以在帮助小字中保留英文术语，但主按钮、标题和错误提示不得要求用户理解英文缩写。

## 导航和状态

- 进入任务后使用顶部步骤条。
- 一次只显示当前步骤。
- 提供“返回首页”“上一步”“下一步”。
- 已完成步骤可以返回查看。
- 发生错误时保留已填写内容和当前步骤。
- 远端写操作只在最终确认后执行。
- 离开未完成流程时提示是否放弃本次填写，不修改工程文件。

## 测试边界

- 所有 Git 写入测试使用系统临时目录中的模拟仓库和 bare 远端。
- 不得对真实 `lens-mechanics` 执行 Commit、Push、Tag、Pull、附件上传或 MR 创建。
- 文件树测试覆盖多级目录、长中文名、空目录、重复文件名、新增、修改和删除。
- 浏览器测试覆盖 1440×900 和 390×844，无横向溢出、按钮重叠或文字遮挡。
