# 小白工作流强化设计

## 目标

让第一次接触 Git 和工程交付系统的工程师，只根据页面上的业务语言即可完成连接、下载、上传、审核与发布跟踪。普通流程不要求用户理解 Token、SSH、Commit、Push、Pull、MR、Tag 或 Branch。

## 全局约束

- 不修改或验证真实机械工程文件；自动化测试使用临时仓库和模拟数据。
- 不在普通页面显示底层 Git 错误或技术缩写。
- 密码、软件访问码和身份钥匙内容不得进入工程目录、日志或渲染进程。
- 所有会改变公司服务器状态的操作继续要求最终确认。
- 删除文件、覆盖风险和版本冲突必须在操作前阻止。
- 保留旧项目级凭据作为兼容后备，新流程统一使用本机连接。
- 本阶段不生成安装包。

## 1. 连接自检

账户页在三步连接流程末尾提供“检查连接”按钮。检查按以下顺序执行：

1. 检查公司项目服务器是否可访问。
2. 使用软件访问码读取当前用户信息，验证访问码和 `api` 权限。
3. 使用本机身份钥匙对当前项目执行只读连接检查。

结果必须拆分显示为“公司网络、软件访问码、电脑身份钥匙”三项。失败时显示具体下一步，不显示原始堆栈或命令输出。检查不创建提交、不上传文件、不修改服务器。

## 2. 新项目自动身份钥匙

“把云端项目下载到这台电脑”只要求：

- 管理员提供的项目下载地址。
- 用户选择的本地保存位置。

后端自动读取本机连接中的身份钥匙和密码。普通页面不显示身份钥匙路径；现有手工路径输入仅保留在折叠的高级设置中。下载成功后项目自动加入项目中心。

## 3. 错误翻译层

建立集中式错误分类器，至少覆盖：

- 公司网络不可达或超时。
- 软件访问码无效、过期或权限不足。
- 身份钥匙未登记或密码错误。
- 本地存在未上传修改，无法安全获取。
- 本地和公司服务器都有新修改。
- 工作版本不存在或无上传权限。
- 交付标签重复。
- 文件被占用、路径无效或磁盘空间不足。

每个错误返回：

- 简短标题。
- 发生了什么。
- 文件是否安全。
- 下一步操作。
- 稳定错误代码，供界面和测试使用。

未知错误显示通用安全提示，并允许在高级信息中查看经过脱敏的技术摘要。

## 4. 风险拦截

上传前执行只读预检：

- 删除的 CAD 或交付文件必须逐项确认。
- 公司服务器存在用户尚未获取的新内容时阻止上传。
- 当前工作版本与用户选择不一致时再次明确确认。
- 本次交付标签已存在时阻止上传并要求更换。
- 没有任何有效修改时不允许创建空记录。

拦截提示必须说明不会丢失本地文件。检查通过后才进入最终确认。

## 5. 项目首页状态

首页每个项目只显示四类业务状态：

- 这台电脑有多少项修改尚未上传。
- 公司服务器是否有同事上传的新内容。
- 是否存在等待管理员处理的审核单。
- 铁炉堡是否已完成发布。

状态旁提供唯一推荐动作，例如“继续上传”“先获取同事修改”“查看审核单”“打开铁炉堡”。真实工作版本名可作为次要信息显示。

## 6. 首次使用清单

首次使用清单包含：

1. 连接这台电脑。
2. 添加或下载一个项目。
3. 完成第一次上传。

完成状态来自真实本地状态，不使用单纯的手工勾选。三项完成后清单自动折叠；用户可以从帮助入口重新展开。状态保存在应用用户数据目录，不进入工程目录。

## 7. 登录与退出

账户页分别显示：

- 公司项目服务器：未连接、已连接、需要重新连接。
- 铁炉堡：需要网页登录、浏览器登录状态无法由本机确认、已由用户打开。

“清除这台电脑的连接”只删除安全存储中的软件访问码、身份钥匙密码和连接状态。生成的身份钥匙文件默认保留，避免误删后无法访问；高级操作中提供单独删除身份钥匙的入口并要求二次确认。退出不修改任何工程文件。

## 架构

### 后端服务

- `ConnectionCheckService`：执行网络、GitLab API 和只读 SSH 检查。
- `FriendlyError`：把底层异常分类成稳定、可展示的结构。
- `ProjectRiskService`：在上传前汇总删除、服务器更新、工作版本和标签风险。
- `CredentialVault`：继续提供本机连接优先、项目级配置后备的读取方式。

### 前端组件

- `ConnectionCheckPanel`：展示三项检查和修复动作。
- `FriendlyErrorNotice`：统一展示标题、安全说明和下一步。
- `ProjectStatusSummary`：首页四项业务状态。
- `FirstRunChecklist`：首次使用进度与重新展开入口。
- 下载、上传和交付向导复用上述状态与错误组件。

## 数据流

1. 渲染进程只发送项目 ID 或用户确认的操作参数。
2. Electron 本地服务从安全存储读取凭据，不把明文返回页面。
3. 检查服务执行只读验证并返回结构化结果。
4. 风险服务在任何写操作前运行；存在阻断风险时不执行 Git 写命令。
5. 页面只依据稳定代码和业务文案呈现结果。

## 测试

- 单元测试覆盖错误分类、连接检查顺序、凭据后备和风险判定。
- API 测试验证检查接口只读、风险失败时写操作未调用。
- 组件测试覆盖三项连接结果、下载简化表单、错误提示、首页状态和首次使用清单。
- 完整测试继续使用临时 Git 仓库，不访问真实公司服务器。
- 浏览器复核桌面与窄屏页面，检查无遮挡、无横向溢出和无普通流程技术术语。

## 完成标准

- 普通用户连接一次后，可在任意项目上传和获取。
- 下载新项目无需填写身份钥匙路径。
- 常见失败均显示文件安全性和明确下一步。
- 高风险操作在写入前被阻止。
- 首页和首次使用清单基于真实状态。
- 全套测试、代码检查和桌面构建通过。
