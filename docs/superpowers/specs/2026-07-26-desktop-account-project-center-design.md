# 桌面账号与项目中心设计

## 目标

把工作台交付为单个 Windows `.exe`。每台电脑由一位工程师使用，程序包含运行所需依赖，并支持使用工程师自己的 GitLab 身份、SSH Key、多个本地项目和不同下载路径。

## 使用模型

- 一台 Windows 电脑对应一个当前工程师。
- 工程师只使用自己的 GitLab 权限和 SSH Key。
- 不保存或使用其他同事的账号、密码或私钥。
- 管理员负责在 GitLab 创建项目并授予工程师权限。
- 程序不替普通工程师创建 GitLab 项目。

## 首次启动

首次启动向导：

1. 填写公司 GitLab 地址。
2. 配置 GitLab API Token，用于读取项目、审核人、上传附件和创建 MR。
3. 选择或导入自己的 SSH 私钥，用于 Clone、Fetch、Pull 和 Push。
4. 验证 GitLab API 和 SSH 连接。
5. 添加本地已有项目，或下载管理员已创建的云端项目。

完成后进入项目中心。后续启动直接使用当前 Windows 用户安全存储中的配置。

## 登录与退出

“登录”是 GitLab API 身份与 SSH 连接的组合状态：

- GitLab API Token 负责 API。
- SSH Key 负责 Git 文件传输。
- 页面分别显示两项是否可用，并给出可执行的修复提示。

“退出登录”：

- 清除程序保存的 GitLab Token和当前身份状态。
- 取消项目与凭据配置的绑定。
- 不删除本地项目文件。
- 不擅自删除用户磁盘上的原始 SSH 私钥。
- 再次使用远端功能前必须重新登录并验证。

## 安全存储

- GitLab Token 使用 Windows Credential Manager 或 DPAPI 加密保存。
- 应用配置只保存凭据引用，不保存明文 Token。
- SSH 私钥不得复制进项目仓库、日志、前端构建产物或安装包。
- 项目配置不得包含密码。
- 错误日志不得输出 Token、私钥内容或完整认证请求头。

## 项目中心

项目中心显示项目列表，每个项目记录：

- 显示名称
- 本地工程路径
- GitLab 项目地址
- 默认工作分支
- 使用的 SSH Key 配置
- 默认审核人
- 默认 Ironforge 下载目录
- 最近同步状态

支持：

### 添加本地已有项目

- 用户选择文件夹。
- 如果已经是 Git 仓库，自动识别远端项目和分支。
- 如果不是 Git 仓库，要求选择管理员创建的 GitLab 项目，然后初始化并连接。
- 不移动或复制原文件。
- 首次上传前展示完整文件清单。

### 把云端项目下载到本机

- 列出当前账号有权访问的管理员已创建项目。
- 用户选择项目、分支或版本标签。
- 用户选择本地目标路径。
- 目标必须为空目录或不存在的子目录。
- 使用内置 Git 和 Git LFS 完成 Clone。

### 项目路径

- 每个项目独立选择并记忆本地路径。
- 更换电脑后重新选择新电脑路径，不复用旧电脑绝对路径。
- 路径失效时停止操作并要求重新定位，不自动搜索整块磁盘。
- 删除项目记录只移除工作台配置，不删除工程文件夹。

## 多项目与 SSH Key

- 一个工程师可以管理多个项目。
- 每个项目可绑定不同 SSH Key。
- Git 子进程按项目生成临时 SSH 命令环境，例如 `GIT_SSH_COMMAND`，不修改用户全局 Git 配置。
- 项目切换后，首页三个任务入口始终作用于当前选中的项目。
- 执行远端操作前再次显示项目名称和本地路径，防止同步错项目。

## 获取同事文件

- 工程师使用自己的权限读取同事已经 Push 到 GitLab 的分支。
- 不需要也不允许选择同事的 SSH Key。
- 获取前展示来源项目、来源分支或标签、目标本地路径和文件差异。
- 本地存在未上传改动时停止。
- 不自动执行可能产生冲突的合并；需要修改时引导用户先处理本地改动。

## Ironforge 下载

- Ironforge 浏览和下载使用当前工程师的授权身份。
- 下载目录每次可选，也可使用项目默认值。
- 默认下载到工程目录之外。
- 下载结果保留项目、标签和交付文件夹层级。
- 导入 Git 项目的 `reference` 必须单独预览并确认。

## 开箱即用 `.exe`

安装包必须包含：

- Electron 运行时
- 前端与本地服务
- 版本锁定的 PortableGit
- Git LFS
- 所需 CA 证书与 SSH 客户端
- 所有 Node 运行依赖

用户电脑不需要预装：

- Node.js
- npm
- Git
- Git LFS
- Python

程序不得依赖系统 `PATH` 中的 Git。所有 Git 调用必须解析到应用资源中的可执行文件。

## 安装与升级

- 支持当前 Windows 用户安装，不要求管理员权限。
- 安装、升级和卸载不得修改或删除工程文件。
- 卸载时保留项目目录；凭据清理由用户明确选择。
- 安装包包含版本号和 SHA-256 校验值。

## 验证

- 在未安装 Git、Git LFS、Node.js 和 npm 的干净 Windows 环境中验证启动。
- 使用模拟 GitLab、模拟 Ironforge 和临时 Git 仓库验证登录、Clone、Fetch、Push、Tag、附件和 MR。
- 验证两个项目绑定不同 SSH Key 时不会串用。
- 验证退出后 API 与 Git 远端操作都不可执行。
- 验证项目记录删除、应用卸载和升级不删除工程文件。
- 真实公司 GitLab 和 Ironforge 联调必须由用户在场逐项确认。
