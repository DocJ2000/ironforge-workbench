# 账户与连接分步向导设计

## 目标

将“账户与连接”从配置项集合改为适合零基础用户的分步向导。每一屏只要求用户完成一件事，并且为每个专业输入项提供通俗名称、用途说明和详细帮助。

## 页面结构

### 首次设置

1. 欢迎页：说明连接只需设置一次，点击“开始设置”进入向导。
2. 公司地址：填写 GitLab 地址和铁炉堡地址。两项均提供问号帮助，保存后进入下一步。
3. 软件访问码：打开 GitLab 创建访问码，粘贴并保存。明确说明它不是登录密码。
4. 电脑身份钥匙：由软件自动创建，不要求用户查找公钥或私钥文件。身份钥匙密码默认收起并标记为可选。
5. 登记电脑：复制电脑登记码，打开 GitLab 添加 SSH Key。
6. 检查连接：检查公司网络、软件访问码和电脑登记状态。只有检查成功后显示设置完成。
7. 完成页：显示连接状态、进入 GitLab 项目入口和软件更新。

顶部只显示“第几步，共几步”和简短步骤名称。每一步提供返回按钮，但不会自动提交、上传或删除工程文件。

### 已完成设置

再次进入账户页面时直接显示简洁总览：

- 公司地址：已保存或需要填写
- 软件访问码：已安全保存或需要设置
- 电脑登记：已连接或需要处理
- 软件版本：当前版本及更新状态

用户可以选择“重新设置连接”，随后进入同一分步向导。

## 软件更新

软件更新是普通功能，不放入“专业显示”。完成页和已完成设置总览均显示：

- 当前版本
- 检查新版本
- 检查过程与最终结果
- 下载新版本
- 重启并安装

所有动作都必须由用户点击触发。

## 专业显示

默认收起，只包含：

- 手动选择已有 SSH 私钥
- SSH 私钥密码
- 手动覆盖 GitLab Token
- 清除这台电脑保存的连接

公钥路径不要求填写。普通用户流程中由软件自动创建钥匙，并只展示可复制到 GitLab 的电脑登记码。

## 状态与错误

- 每一步必须有明确的完成反馈。
- 操作期间按钮显示“正在处理”，避免用户重复点击。
- 错误信息使用通俗语言，并给出下一步应该做什么。
- 检查连接失败时停留在检查页，不清除已经保存的信息。
- 页面刷新或软件升级不会清除安全保存的连接信息。

## 视觉规范

- 页面主体保持单列，最大宽度约 720px。
- 当前步骤为唯一主要卡片，不嵌套其他卡片。
- 每屏只有一个主要按钮。
- 状态统一使用“需要完成、正在处理、已经完成、需要处理”。
- 专业术语仅出现在问号帮助和“专业显示”中。

## 验证

- 测试首次设置的完整前进和返回流程。
- 测试已经配置的电脑直接进入完成总览。
- 测试软件访问码、电脑登记和连接检查的状态反馈。
- 测试软件更新始终位于普通页面。
- 测试专业设置默认收起。
- 测试桌面端凭据接口与现有保存格式保持兼容。
