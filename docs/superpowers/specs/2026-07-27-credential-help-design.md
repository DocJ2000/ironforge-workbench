# Novice GitLab Connection Design

## Goal

让完全不了解 Git、Token、SSH 和文件路径的工程师完成 GitLab 连接，不要求用户预先安装 Git 或手动生成 SSH Key。

## Default Experience

设置页默认显示三步引导，不直接展示技术字段：

1. `让软件连接公司 GitLab`：解释软件访问码的用途，引导用户打开 GitLab Access Tokens 页面并粘贴访问码。
2. `给这台电脑创建身份钥匙`：由软件调用内置 OpenSSH 生成独立 Ed25519 密钥，用户不需要填写路径。
3. `完成连接`：显示公钥、复制按钮、打开 GitLab SSH Keys 按钮，并自动检查本地密钥和 GitLab API 是否可用。

每一步只显示当前需要完成的操作。页面不得要求用户理解 Push、Pull、MR、Token 或私钥等术语。

## User-Facing Language

- `GitLab Token`显示为`软件访问码`，技术名称只放在帮助说明中。
- `SSH 私钥`显示为`这台电脑的身份钥匙`。
- `Push`显示为`上传到服务器`。
- `Pull`显示为`获取同事的新内容`。
- `MR`显示为`提交管理员审核`。

## Contextual Help

- 软件访问码、电脑身份钥匙和身份钥匙密码的标题右侧显示小问号图标。
- 点击后在当前控件下方展开详细步骤，再次点击收起。
- 问号按钮必须提供无障碍名称与展开状态。

## Identity Key Generation

- 默认生成到应用专属用户数据目录，不写入项目。
- 使用内置 `ssh-keygen.exe` 生成 Ed25519 密钥。
- 不覆盖已有密钥；已有密钥时复用并读取对应公钥。
- 用户可选择设置身份钥匙密码，也可留空。
- 生成后只展示公钥；私钥内容永不发送到渲染进程。
- 提供`复制公钥`和`打开 GitLab 添加身份钥匙`。
- 高级用户仍可在`高级设置`中选择已有私钥。

## Connection Verification

- 本地检查密钥文件存在且公钥可读取。
- GitLab API 检查访问码有效。
- 远端 SSH 权限只在不修改仓库的只读命令中验证。
- 失败提示必须说明用户下一步点击哪里，不展示原始 Git 命令。
- 验证成功后显示`这台电脑已连接`。

## Advanced Settings

- GitLab 地址、Token 原始名称、私钥路径和私钥密码收进默认折叠的`高级设置`。
- 已有密钥、多个项目使用不同密钥的用户可以在此修改。
- 任何密码或 Token 均使用 Windows 安全存储，不写入工程文件。

## Testing

- 验证新用户可以从无密钥状态完成生成、复制公钥和保存。
- 验证已有密钥不会被覆盖。
- 验证渲染进程无法读取私钥和已保存 Token。
- 验证问号帮助展开与收起。
- 验证高级设置默认折叠。
- 验证桌面安装包使用内置 OpenSSH，无需系统安装 Git。
