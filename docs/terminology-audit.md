# 小白术语审计

审计标准：假设用户第一次接触 Git 和工程交付系统，页面必须直接说明“要做什么”和“做完会发生什么”。

## 普通页面统一用语

| 技术术语 | 普通页面用语 |
| --- | --- |
| GitLab | 公司项目服务器（首次出现时说明，之后可保留品牌名） |
| Repository / 仓库 | 项目 |
| Branch / 分支 | 工作版本 |
| Commit | 保存本次修改 |
| Push | 上传到公司项目服务器 |
| Pull | 获取同事上传的新内容 |
| Merge Request / MR | 管理员审核单 |
| Merge | 管理员批准并合入正式版本 |
| Tag | 本次交付标签 |
| SSH Key / 私钥 | 这台电脑的身份钥匙 |
| remote / 远端 | 公司项目服务器 |
| output | 交付图纸文件夹 |
| charge.json | 铁炉堡交付清单 |
| Git LFS | 大文件管理（仅在详细信息中显示原名） |

## 保留规则

- `GitLab` 和“铁炉堡”是公司系统名称，可以保留，但首次出现必须解释用途。
- `dev/T2`、`main` 等真实名称必须显示；标签写成“工作版本名称”或“正式版本名称”。
- `SSH`、`Token`、`MR` 等技术词只允许出现在“高级设置”或问号帮助中。
- 文件夹名 `output`、文件名 `charge.json` 属于真实路径，可以在详细信息中显示，主标题不得只写这些名称。
- 错误提示必须同时告诉用户下一步怎么做，不能只显示底层 Git 错误。

## 审计结论

已完成以下整改：

- 上传、获取、历史、概览、工作版本、发布预览和旧弹窗统一使用普通操作语言。
- 软件访问码帮助包含从登录、添加新令牌到复制回软件的完整步骤。
- 账户与连接改为整台电脑统一设置，不再要求选择项目。
- 项目选择只出现在项目中心、上传和获取流程。
- 技术字段只保留在折叠的“高级设置”中。

普通流程已符合本审计标准。真实品牌名、工作版本名、文件路径和高级设置中的技术名称按保留规则继续显示。
